  Task: For every foreign-key constraint declared in ./docs/db/MySQL.sql, modify the matching generated Entity class and DAO class under src/main/java/com/landawn/ofbiz/{entity,dao}/ to add reverse-navigation fields and join helpers.

  Input — canonical FK source:
  Parse the -- FOREIGN KEYS section of ./docs/db/MySQL.sql. Each FK has the form:
  ALTER TABLE `LOCAL_TABLE` ADD CONSTRAINT `FK_NAME`
    FOREIGN KEY (`LOCAL_COL[, LOCAL_COL2, ...]`)
    REFERENCES `REF_TABLE` (`REF_COL[, REF_COL2, ...]`);
  Use the table → entity class mapping already established by scripts/gen_entities_daos.py (UPPER_SNAKE table → PascalCase class; UPPER_SNAKE column → camelCase field).

  ---
  Entity changes (per FK):

  In the local entity class (the table holding the FK column), add a field representing the referenced entity:

  @JoinedBy("localFkField=ReferencedEntity.referencedField")
  @ToString.Exclude
  @EqualsAndHashCode.Exclude
  private ReferencedEntity referencedEntityFieldName;

  Rules:
  - Import com.landawn.abacus.annotation.JoinedBy, lombok.EqualsAndHashCode, and lombok.ToString.
  - Annotation value format: "localFkCol1=RefEntity.refCol1, localFkCol2=RefEntity.refCol2" (comma-joined for composite FKs, both sides in camelCase Java field names — NOT SQL column names).
  - Always add @ToString.Exclude and @EqualsAndHashCode.Exclude on every @JoinedBy field to prevent recursion (Lombok's @Data would otherwise pull joined entities into toString/equals/hashCode).
  - Field-naming rules:
    - Default (single FK to a target entity): plain camelCase of the referenced entity class. E.g., FK productId → Product.productId becomes field product.
    - Disambiguation (2+ FKs from the same local entity to the same target entity): strip a trailing Id/IdFrom/IdTo/etc. from the local FK column's camelCase form, then concatenate with the target entity name. E.g., PARTY_RELATIONSHIP
  has partyIdFrom and partyIdTo both → Party, giving fields partyFrom and partyTo.
    - General disambiguation: derive a prefix by stripping the trailing referenced field name (Id, EnumId, TypeId, etc.) from the local FK column, lowercase-first, then append the target entity name in PascalCase. Examples: originGeoId
  + Geo → originGeo; destinationGeoId + Geo → destinationGeo; partyIdFrom + Party → partyFrom.
  - Place the new @JoinedBy fields after all existing @Column fields, in the order FKs appear in MySQL.sql.
  - Do NOT add @Column to these — they are joined references, not columns.
  - Do NOT touch view entities (views have no FKs anyway, and they're read-only).

  Example A — common case: for DATA_RESOURCE.DATA_RESOURCE_TYPE_ID → DATA_RESOURCE_TYPE.DATA_RESOURCE_TYPE_ID, add to DataResource.java:
  @JoinedBy("dataResourceTypeId=DataResourceType.dataResourceTypeId")
  @ToString.Exclude
  @EqualsAndHashCode.Exclude
  private DataResourceType dataResourceType;

  Example B — disambiguation case: PARTY_RELATIONSHIP has FKs partyIdFrom → Party.partyId and partyIdTo → Party.partyId, so PartyRelationship.java gets:
  @JoinedBy("partyIdFrom=Party.partyId")
  @ToString.Exclude
  @EqualsAndHashCode.Exclude
  private Party partyFrom;

  @JoinedBy("partyIdTo=Party.partyId")
  @ToString.Exclude
  @EqualsAndHashCode.Exclude
  private Party partyTo;
